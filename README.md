<h1 align="center">xngxltuiplayer</h1>

[Bubble Tea](https://github.com/charmbracelet/bubbletea). Скачивает треки по
ссылкам, раскладывает их в локальную библиотеку, показывает обложки и
спектр-визуализацию, умеет собирать плейлисты.

## Скачать готовый билд

Готовые сборки лежат в
[Releases](https://github.com/maximowivan/xngxltuiplayer/releases).

### Windows: установщик

1. Скачайте `xngxltuiplayer-v*-windows-amd64.zip` из Releases и распакуйте
   в любую папку, куда у вас есть запись.
2. Запустите `install_xngxltuiplayer.bat`.
3. Нажмите `Enter`, чтобы поставить в
   `%LOCALAPPDATA%\Programs\xngxltuiplayer`, или введите свою папку,
   например `D:\Apps\xngxltuiplayer`.
4. Установщик берёт файлы из распакованного архива. Если запустить только
   скрипт без `xngxltuiplayer.exe` рядом, он скачает последний релиз с GitHub,
   покажет прогресс в МБ и проверит SHA256.
5. `yt-dlp` и `ffmpeg` ставятся через winget, если их нет. Для обычной
   установки администратор не нужен; winget может запросить UAC для ffmpeg.
   Прогресс скачивания winget показывает сам, а установщик добавляет этапы и
   не скрывает его вывод.
6. Создаются ярлыки на рабочем столе и в меню «Пуск» для текущего
   пользователя. Если Windows Terminal не найден, установщик предложит
   поставить портативный Windows Terminal (~12 МБ, Windows 10 2004+, без
   администратора). Это необязательно: без него плеер работает в режиме
   совместимости. Отказ — `-NoTerminal`, установка без вопроса —
   `-WithTerminal`, принудительно портативный — `-PortableTerminal`.
7. Создаётся uninstaller и запись в «Программах и компонентах».
8. Музыка и `data\` при обновлении сохраняются. Портативный Windows Terminal
   лежит в `terminal\` и при обновлении не затрагивается.

Флаги установщика: `-NoTerminal` — не предлагать терминал, `-WithTerminal` —
поставить без вопроса, `-PortableTerminal` — использовать портативный WT даже
при установленном, `-TerminalZip <path>` — локальный ZIP для офлайн-установки.

Если Windows покажет SmartScreen для `.bat`/`.exe`, выберите
`Подробнее` → `Выполнить всё равно`: исполняемые файлы не подписаны.

### Windows: портативно

Можно не устанавливать, а запускать `xngxltuiplayer.exe` прямо из
распакованной папки. Тогда ярлыки и запись в реестре не создаются, а
`music\` и `data\` лежат рядом с exe. Не используйте для этого
`C:\Program Files` — там нет прав на запись.

Проверка и обновление:

```powershell
.\xngxltuiplayer.exe --check
.\xngxltuiplayer.exe --version
.\xngxltuiplayer.exe --update
```

`--update` скачает последний релиз, покажет прогресс, проверит SHA256, заменит
exe и перезапустит плеер; `music\` и `data\` не затрагиваются. Начиная с 0.4.1
Windows-сборка также проверяет обновления сама при запуске и предлагает
установить новую версию. Первый переход с 0.4.0 на 0.4.1 всё равно нужно
сделать вручную: в 0.4.0 автообновления ещё нет.

`--update` обновляет только сам плеер: чтобы поставить необязательный Windows
Terminal, запустите установщик из нового релиза.

Удаление установленной копии: `uninstall_xngxltuiplayer.bat` в папке
установки или `xngxltuiplayer` в «Программах и компонентах». Музыка и
`data\` сохраняются, если не подтвердить их удаление отдельно.

### Linux

1. Скачайте `xngxltuiplayer-v*-linux-amd64.tar.gz` из Releases и распакуйте:
   ```bash
   tar -xzf xngxltuiplayer-v*-linux-amd64.tar.gz
   ```
2. Запустите:
   ```bash
   ./xngxltuiplayer --check
   ./xngxltuiplayer
   ```
3. Нужен работающий ALSA/PulseAudio/PipeWire и UTF-8-терминал. Полный
   интерфейс с обложкой и truecolor — в современном терминале (GNOME
   Terminal, Konsole, xterm, kitty, WezTerm, Alacritty, foot). На голой TTY
   (`TERM=linux`) автоматически включается ASCII-режим; Windows Terminal для
   Linux не нужен и не существует. `libasound2` обычно уже установлен; для
   сборки из исходников нужен `libasound2-dev`.
4. `--update` и uninstaller — только для Windows. На Linux обновляйтесь,
   распаковывая новый архив; `music/` и `data/` лежат рядом с бинарником и не
   затрагиваются.

Музыку можно сразу положить в `music\` или добавить по ссылке клавишей `a`.
Папки `music\` и `data\` создаются при первом запуске.

## Возможности

- **Офлайн-воспроизведение** MP3, FLAC и WAV через beep + oto; на Windows и
  macOS без CGO, на Linux — через ALSA/CGO.
- **Скачивание по ссылке**: Spotify (отдельный трек), SoundCloud (трек или сет),
  YouTube (видео или плейлист), прямые ссылки на аудио и страницы, которые
  понимает `yt-dlp`. Для плейлистов и сетов есть предпросмотр и пакетная
  очередь.
- **Конвертация в MP3 V0** 48 кГц / стерео через `ffmpeg`, с тегами
  ID3v2.4 (UTF-8) и встроенной обложкой.
- **Обложки альбомов** в truecolor, с кэшем и запасным чтением ID3-тегов,
  записанных в UTF-16. Клавиша `c` (или клик по обложке) открывает большой
  режим на весь экран.
- **Визуализатор**: живой FFT-спектр в правой панели, прижатый к нижней границе
  и растущий вместе с высотой окна; на узких терминалах — компактная строка `FFT`.
- **Эквалайзер**: 10 полос от 31 Гц до 16 кГц, ±12 дБ, preamp, пресеты Flat,
  Bass, Vocal и Electronic. Меняется на лету и сохраняется в сессии.
- **Скорость 0.5–2.0x**: tape-style, тон меняется вместе со скоростью. `[` и `]`
  меняют шагом 0.05, `\` возвращает 1.00x.
- **Логотип и иконка**: оранжевый знак встроен в exe и используется ярлыками,
  проводником и панелью задач.
- **Автообновление библиотеки**: новые, удалённые и переименованные файлы в
  `music/` подхватываются сами, без нажатия `u`. Для сетевых папок есть
  резервный опрос; флаг `-watch off` отключает наблюдение.
- **Поиск дублей и слияние**: группы по исполнителю, названию и длительности;
  можно оставить лучший файл, ссылки в плейлистах и статистика переходят на
  него, а лишние файлы перемещаются в `data/trash/`.
- **Редактирование тегов и обложки**: `e` открывает редактор title, artist,
  album, year и track number для MP3 и FLAC. Клавиша `c` в редакторе выбирает
  новую обложку по пути или drag-and-drop, `x` — удаляет её. Запись атомарная.
- **Медиа-клавиши**: Play/Pause, Next, Previous и Stop. На Windows — глобальные
  hotkeys, на Linux — MPRIS2 (заодно интеграция с GNOME/KDE).
- **Автообновление плеера**: Windows-сборка при запуске проверяет последний
  релиз на GitHub и предлагает обновиться с прогрессом и перезапуском.
- **Темы оформления**: 22 палитры, включая светлые, с заливкой фона всего окна.
  `t`/`T` переключают их, `Ctrl+T` открывает список с превью; выбор
  сохраняется.
- **Кроссфейд**: последние 5 секунд трека плавно перекрываются со следующим
  треком. Работает в обычном порядке, в случайном порядке, при повторе очереди
  и при повторе одного трека.
- **Компактная нижняя панель**: название и исполнитель слева, транспорт по
  центру, громкость справа, прогресс и очередь снизу.
- **Мышь**: выбор и воспроизведение треков, прокрутка, перемотка, громкость
  перетаскиванием, клики по обложке, кнопкам `⇄`/`↻` и транспорту
  `◀◀`/`▶`/`▶▶`.
- **Мультивыделение**: `Ctrl`+клик или `Ctrl+A`, затем массовое добавление,
  удаление, перемещение или перетаскивание в плейлист.
- **Discord Rich Presence**: статус «Listening», название, исполнитель, альбом,
  таймер, пауза и обложка (если у трека есть публичный URL).
- **Плейлисты**: drag-and-drop треков между плейлистами, проверка дублей,
  массовые операции и подтверждение удаления.
- **Поиск** по названию, исполнителю, альбому и имени файла.
- **Русская раскладка**: горячие клавиши работают и в ЙЦУКЕН, а `-ascii`
  включает полный ASCII-режим: рамки, курсоры, бары, спиннер и обложка тоже
  становятся текстовыми.
- **Повтор, случайный порядок, перемотка, громкость** и восстановление
  последнего трека с сохранённой позиции (на паузе).
- **Таймер сна**: `z` переключает 15/30/45/60 минут и выключение; по истечении
  времени воспроизведение ставится на паузу.
- **Сортировка библиотеки**: `o` переключает исполнителя, название, альбом,
  год и недавно добавленные треки.
- **Избранное и недавняя активность**: `f` добавляет трек в избранное;
  в боковой панели есть «Favorites» и «Recent», а также счётчики
  прослушиваний.
- **Импорт и экспорт M3U**: `I` читает `.m3u`/`.m3u8` и создаёт плейлист,
  `E` сохраняет текущий список в M3U8. Относительные пути считаются от
  папки с музыкой.
- **Терминал**: плеер определяет Windows Terminal, VS Code, WezTerm,
  классическую консоль Windows, Linux TTY, `NO_COLOR` и ограничения шрифта.
  Есть три режима: полный Unicode, совместимый (ASCII-символы при Unicode-
  рамках) и полный ASCII. В conhost с растровым шрифтом автоматически
  включается безопасный режим, чтобы не было квадратиков.
- **Надёжность**: атомарная запись JSON с резервной копией `.bak`, журнал в
  `data\logs`, защита от двух одновременных копий плеера и восстановление
  после паники.
- **Портативность**: папки `music` и `data` лежат рядом с `xngxltuiplayer.exe`,
  их можно переопределить флагами.

## Требования

### Windows

- Windows 10/11 с поддержкой ANSI/VT. Полный интерфейс — в Windows Terminal
  или другом современном терминале; в классической консоли (conhost)
  автоматически включается режим совместимости. Windows Terminal не обязателен.
- Папка, куда у вас есть запись. Не запускайте из `C:\Program Files`: рядом с
  exe создаются `music\` и `data\`.

### Linux

- Linux amd64 (x86_64), ALSA или PulseAudio/PipeWire.
- UTF-8-терминал. Полный вид — в современном терминале (GNOME Terminal,
  Konsole, xterm, kitty, WezTerm, Alacritty, foot); на голой TTY работает
  ASCII-режим. Windows Terminal здесь не используется.
- D-Bus сессии для медиа-клавиш и MPRIS; без него плеер работает, но
  интеграция с рабочим столом недоступна.
- Для сборки из исходников: Go 1.27+, GCC/Clang и `libasound2-dev`
  (Debian/Ubuntu) или `alsa-lib-devel` (Fedora).

### Общее

- [`yt-dlp`](https://github.com/yt-dlp/yt-dlp) — только для скачивания.
- [`ffmpeg`](https://ffmpeg.org/) — только для скачивания/конвертации и обложек.
- `ffprobe` (обычно идёт вместе с ffmpeg) — длительность треков; без него
  плеер всё равно работает, но в списке может не быть длительности до первого
  воспроизведения.

Установка через winget (Windows):

```powershell
winget install yt-dlp.yt-dlp
winget install Gyan.FFmpeg
```

После установки перезапустите терминал, чтобы обновился `PATH`.

Для сборки из исходников нужен **Go 1.27+** (см. `go.mod`).

## Быстрый старт

```powershell
# 1. Проверить окружение
.\xngxltuiplayer.exe --check

# 2. Запустить плеер
.\xngxltuiplayer.exe
```

`--check` проверяет терминал (TTY/VT, шрифт, цветовой профиль, режим глифов,
мышь, наблюдение за библиотекой, медиа-клавиши), папки, `yt-dlp`, `ffmpeg`,
`ffprobe`, аудиоустройство на выбранной `-rate` частоте, подключение к Discord
Rich Presence и наличие `data\cookies.txt`.

По умолчанию рядом с исполняемым файлом создаются:

```
xngxltuiplayer.exe
music\                 # аудиофайлы
data\
  covers\              # кэш обложек (JPEG)
  tmp\                 # временные файлы загрузок
  library.json         # кэш метаданных библиотеки
  playlists.json       # плейлисты
  session.json         # громкость, тема, повтор, последний трек
  stats.json           # избранное, прослушивания, недавние треки
  trash\               # дубликаты, перемещённые при слиянии
  player.lock          # защита от второго запуска
  logs\
    xngxltuiplayer.log # журнал работы и ошибок
  discord.json         # необязательно, Discord Rich Presence
  cookies.txt          # необязательно, для ограниченных источников
```

Если запускать через `go run`, папки создаются в текущем каталоге, а не во
временном каталоге сборки.

### Флаги

```
-music <path>   папка с музыкой (по умолчанию .\music)
-data <path>    папка с данными (по умолчанию .\data)
-theme <name>   тема: catppuccin, tokyonight, gruvbox, nord, dracula,
                rosepine, ember и ещё 15 тем из раздела «Темы»
-ui <mode>      auto, full, compat или ascii; auto выбирает по терминалу
-color <mode>   auto, truecolor, 256, 16 или none
-watch <mode>   auto, on или off; следить за изменениями в music/
-rate <hz>      48000 или 44100; 44100 для старых ЦАП/Bluetooth-гарнитур
-download-workers <n>
                число параллельных загрузок, 1-6 (по умолчанию 2)
-ascii          полный ASCII-режим (то же, что -ui ascii)
-icons <mode>   auto, unicode или ascii; управляет только иконками
-update         скачать и установить последний релиз, затем перезапуститься
                (только Windows)
-discord <id>   включить Discord Rich Presence с Application ID
-check          проверить окружение и выйти
-version        показать версию
```

Относительные пути считаются от текущего каталога.

## Скачивание музыки

Нажмите `a`, вставьте ссылку и нажмите `Enter`. Одиночный трек сразу встаёт в
очередь, для плейлиста или сета сначала открывается предпросмотр. Загрузка идёт
в фоне; прогресс виден в модальном окне `d` и в шапке.

Поддерживаются:

| Источник | Что можно | Что нельзя |
| --- | --- | --- |
| Spotify | `open.spotify.com/track/...`, `spotify:track:...`, короткие `spoti.fi`/`spotify.link` | плейлисты, альбомы, исполнители, подкасты |
| SoundCloud | трек или сет `soundcloud.com/user/sets/...` | профили, лайки, репосты |
| YouTube | видео, `youtu.be`, Shorts, Music, плейлисты `/playlist?list=...` | каналы, поиск |
| Прямые ссылки | `.mp3`, `.flac`, `.wav`, `.m4a`, `.ogg`, `.opus`, `.webm` и др. | — |
| Другие страницы | всё, что умеет `yt-dlp` (Bandcamp и т. п.) | — |

Spotify отдаёт только название и обложку через oEmbed, поэтому исполнитель,
альбом и год уточняются в iTunes, а аудио ищется на YouTube. Это может дать
неточное совпадение для редких треков — проверяйте результат в библиотеке.
Плейлисты и альбомы Spotify пока не поддерживаются: используйте их
YouTube/SoundCloud-копию или скачивайте треки по одному.

Для YouTube-плейлиста или SoundCloud-сета после `Enter` открывается
предпросмотр: название, число треков, суммарная длительность и сколько записей
пропущено. `Enter` ставит всё в очередь, `Esc` отменяет. Лимит — 500 треков на
пакет, дубликаты внутри пакета пропускаются. Загрузки идут параллельно:
`-download-workers` задаёт число воркеров (по умолчанию 2, максимум 6).

Что происходит с файлом:

1. `yt-dlp` скачивает лучший аудиопоток во временную папку.
2. `ffmpeg` перекодирует его в MP3 V0, 48 кГц, стерео.
3. Обложка скачивается, обрезается до квадрата и нормализуется в JPEG.
4. В файл пишутся ID3v2.4-теги в UTF-8: название, исполнитель, альбом, год,
   track number, комментарий с исходной ссылкой и обложка.
5. Файл получает имя `Исполнитель - Название.mp3`; при совпадении добавляется
   ` (2)`, ` (3)` и т. д.

Скачанные треки сразу появляются в библиотеке. Если обложку или теги не удалось
записать, трек всё равно сохраняется, а в окне загрузок показывается
предупреждение. Пакетные загрузки сгруппированы по плейлисту или сету; в окне
`d` клавиша `r` повторяет выбранный failed-трек, `R` — все failed, `c`/`x`
отменяет выбранный, `X` — все активные.

### Ограниченные источники и cookies

YouTube иногда требует вход («Sign in to confirm you're not a bot»), а
SoundCloud/Spotify могут ограничивать регион. Для YouTube можно экспортировать
cookies браузера в формате Netscape и положить файл в:

```
data\cookies.txt
```

`yt-dlp` подхватит его автоматически. Файл не публикуйте: в нём могут быть
токены сессии.

В окне загрузок: `↑` `↓` — выбор, `r` — повторить failed, `R` — повторить все
failed, `c`/`x` — отменить выбранную, `X` — отменить все активные, `C` —
очистить завершённые, `a` — добавить ссылку или плейлист.

### Эквалайзер и скорость

`Q` открывает эквалайзер. `←`/`→` выбирают полосу, `↑`/`↓` меняют её на 1 дБ,
`0` сбрасывает полосу, `1–4` включают пресеты Flat/Bass/Vocal/Electronic,
`-`/`+` меняют preamp, `Tab` листает пресеты. Изменения слышны сразу и
сохраняются в `data/session.json`.

`[` и `]` меняют скорость на 0.05x, `\` возвращает 1.00x. Это tape-style:
вместе со скоростью меняется тон. Скорость применяется к текущему треку и ко
всем следующим, позиция и кроссфейд остаются корректными. Бейдж `1.25x` в
плеере показывает, что скорость не обычная.

В окне помощи: `↑` `↓` / `PgUp` `PgDn` — прокрутка.

В редакторе тегов: `Tab`/`↓` — следующее поле, `Shift+Tab`/`↑` — предыдущее,
`Ctrl+S`/`Enter` — сохранить, `Esc` — отмена. Клавиша `c` переходит к полю
обложки (можно вставить путь или перетащить файл в терминал), `x` — удалить
обложку. Поддерживаются MP3 и FLAC; картинка нормализуется в JPEG.

В окне дублей: `↑`/`↓` — выбрать файл, который оставить; `n`/`p` — следующая
или предыдущая группа; `Enter` — слить; `Esc` — закрыть. Лишние файлы
перемещаются в `data/trash/`, а не удаляются сразу.

### Мышь

Мышь включается автоматически, если терминал её поддерживает. В conhost и на
Linux TTY она отключается, а подсказки переключаются на клавиатуру; все
действия остаются доступны с клавиатуры (громкость — `-`/`=`).

- клик по треку — выбрать, двойной клик — играть;
- `Ctrl`+клик — добавить/убрать трек из мультивыделения;
- перетащите трек (или всё выделение) на плейлист слева: из «All tracks»,
  «Favorites» и «Recent» трек копируется, из другого плейлиста — переносится;
- клик по плейлисту, «Favorites» или «Recent» слева — открыть его;
- колесо — прокрутка списка треков, плейлистов и окна загрузок;
- клик по обложке — полноэкранный режим, клик по большой обложке — закрыть;
- клик по полосе прогресса — перемотка;
- клик по `◀◀` / `▶` / `▶▶` в нижней панели — предыдущий трек, пауза/плей,
  следующий трек;
- громкость: клик или перетаскивание по длинному ползунку, кнопки `−`/`+`,
  колесо над строкой плеера;
- иконки `⇄` и `↻` в строке плеера кликабельны.

Когда мышь включена, терминал перестаёт выделять текст обычным перетаскиванием.
Для копирования используйте `Shift`+перетаскивание (в Windows Terminal и
большинстве других эмуляторов).

Иконки `⇄`, `↻`, `▣`, `◐` — обычные Unicode-символы из исходников, без
внешних файлов и шрифтов. Пауза использует текстовую `║`: символ `⏸` в
Windows Terminal часто подменяется цветным эмодзи и выбивается из интерфейса.
Если ваш терминал не показывает эти символы, запустите с флагом `-ascii`:
весь интерфейс станет текстовым, включая рамки и полосы. Флаг `-icons ascii`
меняет только иконки, оставляя Unicode-рамки.

### Автообновление

На Windows плеер при каждом запуске тихо проверяет последний релиз на GitHub.
Если версия новее, появляется окно с текущей и новой версией:

- `Enter` — скачать обновление с прогрессом, проверить SHA256, распаковать и
  перезапустить плеер;
- `Esc` — отложить; клавиша `U` откроет предложение снова;
- при ошибке сети или проверки плеер продолжает работать, причина пишется в
  `data\logs`.

`music\`, `data\`, `terminal\` и настройки при обновлении не затрагиваются.
Автообновление работает только в Windows-сборке; на Linux обновляйтесь новым
архивом. Первый переход с 0.4.0 на 0.4.1 нужно сделать вручную — в 0.4.0
автопроверки ещё нет.

### Медиа-клавиши

Плеер перехватывает Play/Pause, Next, Previous и Stop:

- **Windows** — глобальные hotkeys, пока плеер запущен. Системного оверлея
  Windows с обложкой и названием (SMTC) в 0.4.1 нет.
- **Linux** — MPRIS2 через D-Bus: работают клавиши рабочего стола и виджет
  «сейчас играет» в GNOME/KDE.
- Если клавиши уже заняты другим плеером, Windows может не отдать их; плеер
  продолжит работать, причина будет в `data\logs`.

### Терминал, режимы и запуск от администратора

TUI рисует символами в чужом терминале, поэтому вид зависит от шрифта и
поддержки цветов. Плеер выбирает режим автоматически:

| Режим | Где включается | Что видно |
| --- | --- | --- |
| `full` | Windows Terminal, VS Code, WezTerm, kitty, современный Linux-терминал | текущий Unicode-интерфейс, truecolor, обложка полублоками |
| `compat` | conhost с TrueType-шрифтом | Unicode-рамки и обложка, но ASCII-иконки, курсоры, прогресс, громкость и FFT |
| `ascii` | conhost с растровым шрифтом, `TERM=linux`, `dumb`, не-UTF-8 локаль, `-ascii` | только ASCII: `+ - \|`, `#`, `=`, ASCII-обложка |

В Windows Terminal, VS Code, WezTerm, Alacritty и kitty включается полный
режим. В классической консоли Windows (conhost) нет fallback-шрифта, поэтому
включается `compat` или `ascii`: `⇄`, `↻`, `▣` и другие символы иначе
превращаются в квадратики. На Linux Windows Terminal не нужен: полноценный
вид даёт обычный современный эмулятор, а на голой TTY работает `ascii`.

Отдельно распознаётся случай, когда Windows Terminal выбран терминалом по
умолчанию и плеер запущен двойным кликом из Проводника: в этом процессе нет
переменной `WT_SESSION`, поэтому плеер проверяет класс консольного окна
(`PseudoConsoleWindow`). Такой запуск считается современным терминалом.

При запуске от администратора Windows часто открывает именно conhost, даже если
обычные окна идут в Windows Terminal. Плееру администратор не нужен: запускайте
обычный ярлык. Установщик создаёт ярлык через Windows Terminal, если он
установлен, либо через портативный Windows Terminal, если вы согласились его
поставить. Иначе ярлык запускает exe напрямую в режиме совместимости.

Принудительно выбрать режим можно флагами:

```powershell
.\xngxltuiplayer.exe -ui auto        # по умолчанию
.\xngxltuiplayer.exe -ui full        # даже в conhost (если шрифт умеет)
.\xngxltuiplayer.exe -ui compat      # Unicode-рамки + ASCII-символы
.\xngxltuiplayer.exe -ui ascii       # полный ASCII
.\xngxltuiplayer.exe -ascii          # то же, что -ui ascii
.\xngxltuiplayer.exe -color 256      # 256 цветов вместо truecolor
.\xngxltuiplayer.exe -color none     # без цвета, только текст
```

`--check` показывает программу терминала, TTY/VT, шрифт, цветовой профиль,
режим глифов, мышь, наблюдение за `music/`, медиа-клавиши и рекомендацию.
`NO_COLOR=1` и `CLICOLOR=0` автоматически отключают цвет. Если conhost пишет,
что VT выключен,
отключите «Использовать устаревшую консоль» в свойствах окна или запустите
плеер в Windows Terminal.

Если в Windows 10 нет Windows Terminal, установщик может скачать официальный
портативный ZIP (Windows 10 2004+, без администратора). Он кладётся в
`terminal\` рядом с плеером и не затрагивает системную установку. Без него
плеер полностью работоспособен в `compat`/`ascii`.

### Темы

`t` переключает темы вперёд, `T` — назад, `Ctrl+T` открывает список с живым
превью. Доступны 22 палитры:

- Catppuccin Mocha, Macchiato, Frappe, Latte
- Tokyo Night, Tokyo Night Storm
- Gruvbox, Gruvbox Light
- Nord, Dracula, Ember
- Solarized Dark, Solarized Light
- One Dark, Monokai, Kanagawa, Everforest, Nightfox
- Rose Pine Moon, Rose Pine Dawn
- GitHub Dark, GitHub Light

Тема заливает фон всего окна, а цвета текста, выделения и уведомлений подобраны
с запасом по контрасту, включая светлые варианты. Выбранная тема сохраняется в
`data\session.json` и применяется при следующем запуске. Тему можно задать сразу
при старте:

```powershell
.\xngxltuiplayer.exe -theme nord
```

Обложки в терминале рисуются полублоками `▀`: две цветные точки на ячейку.
Это универсальный способ, но он ограничивает чёткость — большой режим `c`
даёт примерно в 2–3 раза больше точек. В `compat` обложка остаётся
полублочной, если шрифт её поддерживает; в `ascii` и при `-color none`
вместо неё рисуется ASCII-заглушка. Настоящая фотографическая обложка
требует графических протоколов вроде sixel или Kitty graphics, которые
поддерживаются не всеми терминалами, поэтому по умолчанию используется
полублочный рендер.

### Discord Rich Presence

Плеер может показывать в Discord статус «Listening» с названием трека,
исполнителем, альбомом, таймером, состоянием паузы и обложкой.

Rich Presence включён по умолчанию с публичным Application ID
`1563968728352161852` — создавать своё приложение и что-то настраивать не
нужно. Application ID не является секретом: он только определяет, под каким
именем и с какими ассетами Discord показывает активность. Не публикуйте
`client_secret` и токен бота — они для Rich Presence не нужны.

1. Запустите Discord для Windows. Плеер сам подключится к локальному IPC и
   будет переподключаться, если Discord запустится позже.
2. Если нужен свой Application ID, запустите:
   ```powershell
   .\xngxltuiplayer.exe -discord 123456789012345678
   ```
   ID сохранится в `data\discord.json`, и флаг больше не понадобится.
3. Чтобы отключить интеграцию, создайте `data\discord.json`:
   ```json
   {
     "enabled": false
   }
   ```
   Шаблон с публичным ID лежит в `discord.example.json`.

`fallback_image` — необязательный ключ ассета из Discord-приложения или
публичный URL картинки на случай, если обложку трека найти не удалось.
`activity_type` по умолчанию `2` (Listening).

Обложки: при скачивании сохраняется URL исходной обложки. Для старых файлов
плеер берёт исходную ссылку из тега (Spotify, YouTube, SoundCloud и т. п.) и
достаёт оттуда публичную картинку, а если не вышло — ищет в iTunes. Discord
умеет показывать только публичные URL — встроенную в MP3 картинку отправить
нельзя. Если публичной обложки нет, покажется иконка приложения Discord или
`fallback_image`.

При паузе таймер убирается, а в статусе появляется `Paused 0:42 / 3:21`.
Проверить конфигурацию можно через `.\xngxltuiplayer.exe --check`.

### Плейлисты

1. Нажмите `P`, введите имя, `Enter`.
2. Выберите один или несколько треков (`Ctrl`+клик или `Ctrl+A`) и нажмите `x`.
3. Выберите плейлист стрелками и подтвердите `Enter`. В списке видно `✓`, если
   все выбранные треки уже там, и `◐`, если совпадает только часть. Повторно
   добавить один и тот же трек нельзя — дубликаты пропускаются.
4. Чтобы открыть плейлист, переключитесь на библиотеку (`Tab`), выберите его и
   нажмите `Enter`.
5. Перетащите треки мышью на другой плейлист слева — они перенесутся. Из «All
   tracks», «Favorites» и «Recent» треки копируются в плейлист.
6. `D`/`Delete` в открытом плейлисте убирает треки **только из плейлиста**,
   файлы остаются на диске. В окне подтверждения `d` переключает на удаление
   с диска. `X` делает то же быстро, без подтверждения. `D` в фокусе
   библиотеки удаляет сам плейлист; аудиофайлы при этом тоже остаются на диске.

Плейлисты хранятся в `data\playlists.json` как упорядоченные списки абсолютных
путей.

### Избранное и недавние

`f` добавляет выбранный трек (или всё выделение) в избранное и убирает его
обратно. В левой панели есть разделы **Favorites** и **Recent**; Recent
показывает до 50 последних прослушанных треков. Счётчики прослушиваний
хранятся в `data\stats.json`.

### M3U

- `I` — импорт `.m3u`/`.m3u8`. Относительные пути считаются от папки самого
  плейлиста, затем треки ищутся в библиотеке. Создаётся новый плейлист с именем
  файла; при совпадении имени добавляется ` (2)`.
- `E` — экспорт текущего списка в `.m3u8`. Если путь относительный, файл
  создаётся в папке с музыкой. Экспортируются только существующие в библиотеке
  треки.
- Поддерживается расширенный формат `#EXTINF` (исполнитель, название,
  длительность); удалённые URL не импортируются.

### Удаление треков

В «All tracks» `D` (или `Delete`) удаляет выбранные треки **с диска** и убирает
их из всех плейлистов. В открытом плейлисте то же сочетание сначала предлагает
убрать треки только из плейлиста; нажмите `d` в окне подтверждения, чтобы
перейти к удалению файлов. Сначала всегда открывается окно подтверждения
(`y`/`Enter` — подтвердить, `Esc` — отмена), даже для одного трека. Если
удаляется играющий трек, воспроизведение сначала останавливается — это важно
на Windows, где открытый файл нельзя удалить. Для массового удаления выберите
треки через `Ctrl`+клик или `Ctrl+A`.

## Восстановление сессии

При выходе сохраняются громкость, повтор, случайный порядок, открытый плейлист,
тема, последний трек и позиция. При следующем запуске трек восстанавливается на паузе,
аудиоустройство не открывается до первого `Space`. Это позволяет запускать
плеер без звуковой карты и без лишнего шума.

## Сборка

### Windows

```powershell
go mod tidy
go test ./...
.\build.ps1                      # локальная dev-версия
.\build.ps1 -Version 0.2.0       # версия попадёт в --version
.\xngxltuiplayer.exe --check
```

Или просто:

```powershell
.\build.bat
```

Для установки зависимостей и сборки в один шаг:

```powershell
.\setup.ps1
```

Скрипты используют `winget`, если `yt-dlp`/`ffmpeg` не найдены. После установки
может понадобиться новый терминал.

### Linux

Нужны CGO и заголовки ALSA, потому что `oto` использует ALSA:

```bash
# Debian / Ubuntu
sudo apt update
sudo apt install -y build-essential libasound2-dev

# Fedora
# sudo dnf install -y gcc alsa-lib-devel

# Arch
# sudo pacman -S --needed base-devel alsa-lib

CGO_ENABLED=1 go build -trimpath -ldflags "-s -w -X main.version=0.2.0" -o xngxltuiplayer .
./xngxltuiplayer --check
./xngxltuiplayer
```

Сборка с `CGO_ENABLED=0` на Linux не работает: `oto` не сможет подключиться к
ALSA. Кросс-компиляция с Windows на Linux тоже требует Linux C-тулчейн, поэтому
проще собирать на Linux или использовать готовый архив из Releases.

На macOS `oto` работает через CoreAudio; сборка без CGO:

```bash
go build -trimpath -ldflags "-s -w -X main.version=0.2.0" -o xngxltuiplayer .
```

## Решение проблем

**`yt-dlp` или `ffmpeg` не найден.** Установите их и перезапустите терминал.
Проверьте `.\xngxltuiplayer.exe --check`. В PowerShell PATH можно обновить командой:

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')
```

**Нет звука.** Проверьте `--check`: строка `Audio output` должна быть `ok`.
Убедитесь, что громкость не на нуле (`=`), трек не на паузе (`Space`), а
устройство вывода доступно другим приложениям. Аудиоустройство открывается
только при первом воспроизведении.

**Spotify: HTTP 451.** Spotify блокирует oEmbed в регионе. Попробуйте VPN или
скачайте трек с другого источника.

**SoundCloud: таймаут.** Сеть может блокировать SoundCloud. Проверьте
подключение/VPN; приложение покажет понятную ошибку.

**YouTube: «Sign in to confirm you're not a bot».** Положите `cookies.txt` в
`data\` (см. выше) или обновите `yt-dlp`:

```powershell
winget upgrade yt-dlp.yt-dlp
```

**В списке нет длительности.** Установите `ffprobe` (идёт с ffmpeg) и нажмите
`u` для пересканирования. Длительность также подхватывается при первом
воспроизведении.

**Обложка не отображается.** Некоторые MP3 используют UTF-16 ID3-теги, которые
основная библиотека не читает; для них есть запасной парсер. Если обложки нет
в файле, плеер покажет заглушку. Кэш можно очистить, удалив `data\covers`.

**Кракозябры в тегах.** Приложение пишет UTF-8 и читает UTF-16 fallback-парсером;
сторонние файлы с другими кодировками могут отображаться некорректно.

**Discord статус не появляется.** Убедитесь, что Discord для Windows запущен,
Application ID указан верно, а в `data\discord.json` стоит `"enabled": true`.
Проверьте `.\xngxltuiplayer.exe --check`: строка
`connection: ok - Discord IPC handshake succeeded` означает, что плеер
достучался до Discord. Rich Presence не работает в браузере и на мобильном
Discord. Свой статус виден в поповере профиля (клик по аватару в левом нижнем
углу Discord); в списке участников он может быть свёрнут в «+1» или иконку
ноты.

**`--check` пишет `access denied`.** Discord запущен от имени администратора,
а плеер — обычным пользователем (или наоборот). Windows не пускает процесс
с меньшими правами к IPC-пайпу Discord. Варианты:

1. Полностью закройте Discord (значок в трее → Quit Discord) и запустите его
   обычным двойным кликом, без «Запуск от имени администратора». Если Discord
   снова стартует от админа, снимите флаг «Запускать эту программу от имени
   администратора» в свойствах ярлыка, а также проверьте флаг совместимости
   `RUNASADMIN` у `...\Discord\Update.exe` (`Свойства → Совместимость`).
2. Запустите сам плеер от имени администратора. Это тоже работает, но
   drag-and-drop из Explorer может не работать, а `yt-dlp` и `ffmpeg`
   унаследуют повышенные права.

Подробности подключения пишутся в `data\discord.log`.

**Статус включён, но не виден.** В Discord откройте
`Настройки → Данные и конфиденциальность → Приватность профиля →
Конфиденциальность активности` (или введите «активность» в поиск настроек).
Включите «Публиковать активность» и проверьте «Где я публикую активность»:
активность должна публиковаться хотя бы на одном сервере. Если у аккаунта
выбран статус «Невидимка», активность тоже не показывается.

**Квадратики вместо иконок и другой шрифт.** Скорее всего, плеер запущен в
классической консоли (conhost), особенно если это запуск от администратора.
Плеер автоматически выбирает `compat` или `ascii`, но полный Unicode-вид
зависит от шрифта: у conhost нет fallback-шрифта. Варианты:

1. Запускайте ярлык обычным способом; если установщик предложил портативный
   Windows Terminal, ярлык уже ведёт в него.
2. Откройте вручную:
   ```powershell
   wt.exe -d "D:\Apps\xngxltuiplayer" "D:\Apps\xngxltuiplayer\xngxltuiplayer.exe"
   ```
3. Если Windows Terminal нет и ставить не хочется, используйте `-ui ascii`:
   интерфейс станет полностью текстовым, но перестанет зависеть от глифов.

Проверить режим: `.\xngxltuiplayer.exe --check`, раздел `Terminal` — там
видны `font`, `vt`, `color`, `glyphs` и рекомендация.

**Плеер пишет, что VT/ANSI не поддерживается.** В свойствах окна консоли
снимите «Использовать устаревшую консоль» или запустите плеер в Windows
Terminal. Это ограничение самой консоли, а не плеера.

**На Linux всё в квадратиках или не двигается курсор.** Проверьте `TERM` и
локаль: для голой TTY (`TERM=linux`) или `dumb` включается ASCII-режим, мышь
недоступна. Для полного вида нужен современный UTF-8-терминал и шрифт с
нужными глифами; `-ui ascii` принудительно включает безопасный режим.

**Плеер пишет «another player is already using…».** Уже запущена другая копия
с той же папкой `data\`. Закройте её. Это защита от одновременной записи
плейлистов и сессии.

**Файл состояния повреждён.** Плеер хранит резервную копию `.bak` рядом с
`library.json`, `playlists.json`, `session.json` и `stats.json` и восстанавливает
её автоматически. Если повреждён `playlists.json` и резервная копия тоже не
читается, плеер запускается с пустым списком, а повреждённый файл сохраняет как
`playlists.json.corrupt-ГГГГММДД-ЧЧММСС`. Подробности есть в
`data\logs\xngxltuiplayer.log`.

**Слишком маленький терминал.** Минимальный размер — 54×16. Разверните окно или
уменьшите шрифт.

## Ограничения

- Spotify: поддерживаются только отдельные треки. Плейлисты и альбомы Spotify
  пока отклоняются — используйте YouTube/SoundCloud-копию.
- YouTube-плейлисты и SoundCloud-сеты поддерживаются, но зависят от `yt-dlp`:
  приватные, удалённые и регионально заблокированные записи пропускаются.
- Метаданные Spotify неполные, поэтому возможны неточные совпадения при поиске
  аудио на YouTube.
- Нет жанра/BPM, ReplayGain и синхронизации между устройствами.
- Скорость — tape-style, с изменением тона. Pitch-preserving time-stretch не
  поддерживается.
- Эквалайзер и скорость глобальные: применяются ко всем трекам и сохраняются
  между запусками. При сильном бусте используйте preamp, чтобы не клиппилось.
- Редактор тегов и обложки поддерживает MP3 и FLAC; WAV/M4A/OGG не
  редактируются. Обложка нормализуется в JPEG и обрезается до квадрата.
- Поиск дублей использует нормализованные теги и длительность; окончательное
  решение всегда за пользователем. Лишние файлы попадают в `data/trash/`,
  чистить её нужно вручную.
- Медиа-клавиши на Windows работают как глобальные hotkeys без системного
  оверлея; если клавиши заняты другим плеером, регистрация может не удаться.
  Linux MPRIS реализован, но на живом desktop ещё требует проверки.
- Аудиовыход по умолчанию 48 кГц. Если устройство поддерживает только 44,1 кГц,
  запустите с `-rate 44100`: oto допускает только один аудиоконтекст на процесс,
  поэтому автоматически переключиться после ошибки нельзя.
- Удаление трека необратимо: файл удаляется с диска. Слияние дублей безопаснее:
  оно перемещает файлы в `data/trash/`.
- Discord Rich Presence требует запущенный Discord для Windows и Application
  ID из Developer Portal. Обложка должна быть публичным URL; встроенную в MP3
  картинку Discord не принимает.
- Скачивайте только тот контент, на который у вас есть права. Приложение не
  обходит DRM и не предоставляет доступ к платному контенту.
- Linux-архив собирается для amd64. Для ARM64 и других архитектур собирайте из
  исходников.
- Windows Terminal не обязателен, но полный Unicode-вид зависит от терминала и
  шрифта. На Win10 без WT работает режим совместимости; портативный WT требует
  Windows 10 2004+.
- В `ascii`/`compat` обложка и FFT упрощены, а темы могут выглядеть иначе из-за
  16-цветного профиля.
- `--update`, автообновление, uninstaller и скрипты `build.ps1`/`setup.ps1` —
  только Windows. На Linux обновление вручную, новым архивом. Обновление
  заменяет только exe и документацию; для опционального WT запустите установщик
  из релиза.
- Discord Rich Presence проверен на Windows. На Linux Unix-сокеты Discord
  реализованы, но отдельно не тестировались.
